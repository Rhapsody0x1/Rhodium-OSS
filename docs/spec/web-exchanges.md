# 对话页的往来行、宽度和刻度条规格

这篇回答：2026-11-20 定的对话页改版要做成什么样：槽位之间的往来收成一行往来行、在原处展开，`rh send` 发给你的话怎么显示，工具折叠行展开后不重复摘要，对话栏的三档宽度，右边的刻度条；服务端要给页面补哪些标记，`rh send` 怎么从标准输入读正文，系统提示和回执怎么改；怎么测、怎么验收、明确不做什么，怎么拆工单。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[架构](../architecture.md)、[v1 规格](v1.md)、[网页对话界面规格](web-chat.md)、[网页图片、复制和引用规格](web-images.md)、[网页放大模式规格](web-maximize.md)

这些在 2026-11-20 看过两轮原型以后定下。各项事实写在上游，这里不重复，只写需求、做法、测试和交付：

- 行为：[产品说明](../product.md) §5.5（内部回合的最终回复只写一句现状）、§5.9（`rh send` 的正文可以从标准输入给，没推送时的回执）、§7“对话页的往来行、宽度和刻度条”。
- 消息块的新标记：[架构](../architecture.md) §7.7。`rh` 读标准输入：[架构](../architecture.md) §9.1。
- 词：[往来行](../../GLOSSARY.md)、[刻度条](../../GLOSSARY.md)、[内部回合](../../GLOSSARY.md)。刻度条就是讨论时说的“右侧时间线”，改名是为了不和详情里的“对话时间线”混。
- 这里换掉[网页图片、复制和引用规格](web-images.md)故事 562 里“在那次调用的位置”的说法：内部回合里 `rh send` 发给你的，跟在往来行后面。你的回合里的照旧。

这篇用到几个词：

- 主线：对话页从上到下那一串，不算往来行展开以后的内容。
- 你的回合：回复交给你的回合，见[产品说明](../product.md) §7“对话页的往来行、宽度和刻度条”。别的都是[内部回合](../../GLOSSARY.md)。
- 小结：内部回合里最后一次工具调用之后 agent 说的话，也就是它的最终回复。它写给你，但不推到 IM。
- 过程：工具调用、思考，和内部回合里工具调用之间的短话。
- 发给你的：agent 用 `rh send me`、`rh send <平台名或 Bot 名>` 发的。
- 宽、窄：按对话栏自己的宽度分，40rem（640px）起算宽。手机竖着是窄，宽屏分栏里的对话是宽。

## 问题

- 槽位之间来回多时，你要的回答被埋。一段真实对话里，一个回答后面压着 4 个内部回合、46 块、3760 字。
- 内部回合的最终回复是写给你的，却夹在别的槽位的消息中间，看起来像回给对方的。
- agent 在内部回合里常把 `rh send me` 说过的话在最终回复里再讲一遍。没推送时的回执还叫它“之后要说的话写在回复里”。
- `rh send me` 的正文只能写在命令行上，多行和 Markdown 要和 shell 的引号较劲；单个换行在网页上被并成一行。
- 工具折叠行展开以后，行上的摘要和下面每一行说的一样。
- 宽屏上对话栏固定 48rem，表格、代码多时窄。长对话里找自己说过的一句话只能往上翻。

## 方案

- 按“这句话写给谁”分：你、某个槽位，或者没有人。主线上只留你的话、写给你的话、点开才看的行。
- 两段写给你的话之间，槽位之间的东西收成一行往来行。行上露最后一句话的第一行，点一下原处展开。
- 发给你的整条显示在主线上，前面带铃铛，排版和 agent 的回复一样，单个换行照原样换行。
- 服务端在消息块上标出：回合从哪开始、谁开始的，哪些消息是回合中途并进来的，谁发来的，发给了哪个槽位。页面不再拆来源行和命令文字。
- `rh send` 的正文可以从标准输入给。系统提示改成：内部回合里要你看的走 `rh send me`，最终回复只写一句现状。
- 工具折叠行和其中每一步展开后，行上只留名字或步数。
- 对话页的“⋯”里加三档宽度。对话右边一条刻度条，一条短横对应你的一句话或一行往来行。

## 实现决定

### 消息块的新标记

`begins`、`queued`、`sender`、`out` 和后台任务那一块，规则都写在[架构](../architecture.md) §7.7。页面这边只多一条：

- 页面最早一块不是回合开头时（翻页停在回合中间），这些块先照你的回合显示，往上翻到回合开头再重新分段。

### 主线怎么分段

页面先照现在的办法把工具调用折成折叠行，再按回合分段：

1. 每个带 `begins` 的块开始一个回合。
2. 你的回合：照现在的样子进主线。其中带 `sender` 的插进来的消息，和工具块上的 `out`，收进一段往来，放在这个回合最后一块后面。那次调用本身照旧在折叠行里。
3. 内部回合：找第一条 `queued`、不带 `sender` 的你的话，那是你插话的地方。
   - 这之前的整个进往来：开头的来信（或者后台任务那一行），中途的来信，过程，发出的消息，系统行，小结。
   - 从你的话起，照你的回合处理（第 2 条）。
4. 过程怎么切：
   - 最后一次工具调用之前 agent 说的话是短话，并进过程，成为折叠行里的一步。
   - 最后一次工具调用之后的话是小结，几段连着的并成一条。
   - 一条来信或一条发出的消息，把过程断开。
   - 一次调用只是发 `rh send` 给槽位、发成功了，不列进过程：那条消息就是它。发失败的照列，好让你点开看报错。
5. 相邻的往来并成一行，不管中间有几个回合、几个槽位。下面这些把它断开：你的话，你的回合里 agent 的话和折叠行，发给你的那一条。
6. 内部回合里发给你的，那次调用照旧在过程里，内容整条放在这一行往来行后面，断开往来（第 5 条）。

### 往来行：收起

```
宽：
╭──────────────────────────────────────────────────────────────────╮
│ [◎] dev-codex   dev-codex 又问了两处，我都同意了，两处都是…  10:23  › │
╰──────────────────────────────────────────────────────────────────╯
窄：
╭────────────────────────────────────╮
│ [◎] dev-codex 又问了两处，我都同… › │
╰────────────────────────────────────╯
```

- 一条淡蓝描边的圆角行，底色是 `--running` 调淡的颜色，明暗两套。照原型 `ThreadLine` 的样子。
- 从左到右：头像、名字（只在宽时有）、预览、时间（只在宽时有）、朝右的箭头。
- 头像：
  - 这段往来里的槽位，按第一次出现的顺序，几个就叠几个（22px 圆角方块，同列表里的槽位头像：agent 的图标，没有就是名字的第一个字）。
  - 只有本槽位发出的、没有收到的：本槽位头像、一个小箭头、对方头像。
  - 收到的、两边都有的：对方头像。
  - 没有槽位的：后台任务是任务图标；只有 Rhodium 通知的是 Rhodium 的图标。同样大小的圆角方块。
- 名字：几个槽位用顿号并列。和本槽位同一个工作区的，只写槽位名。最多占行宽的 45%，多了截断。没有槽位的写“后台任务”或“Rhodium”。
- 预览：这段往来里最后一句话的第一行，去掉 Markdown 的标题、列表、加粗和代码记号，一行截断，宽窄都只一行。
  - 最后一句是小结：正文色的 80%。
  - 最后一句是消息：灰色。收到的前面带 ↙ 图标；发出的带 ↗ 图标，头像已经是“本槽位、箭头、对方”时不带。
  - 发出的消息没发出去，或者回合以出错、被打断的系统行结束：后面带现有的红色失败标记。
- 时间：最后一句话的时间，同主线上的时间格式。
- 没有计数（原型里的 ↙1 ↗1 去掉）。
- 整行是一个按钮：`aria-expanded`，`aria-label` 写“和 <名字> 的往来”。

### 往来行：展开

- 行本身一个像素都不动：头像、名字、时间、箭头都在原处，箭头原地转 90 度，预览隐去但留着位置，行高不变。窄时预览的位置换成名字。
- 内容出现在行下面，左边一条竖线，和工具折叠行展开的样子一样。
- 不吸顶。
- 收起时这一行留在原来的屏幕位置：收起前记下它离屏幕顶多远，收起后把滚动位置补回来。
- 里面按时间排，回合之间空约 20px，回合里面空约 8px：

| 东西 | 样子 |
|---|---|
| 收到的消息 | 一行小字头：对方头像（18px）、名字（链到它的对话页）、时间。子槽位汇报在名字后加一个汇报图标，不写字。正文在下一行，13px，灰色，宽时缩进到头像右边。正文照原样显示，不按 Markdown。 |
| 发出的消息 | 小字头：本槽位头像、本槽位名字（只在宽时有）、→、对方头像和名字、时间。没发出去的带红色失败标记。正文同上。 |
| 过程 | 现有的工具折叠行。短话是其中一步，整句显示，没有箭头。正在跑的调用用现有的“正在跑”那一行。 |
| 小结 | 没有头像和名字。正文字号、正文色、Markdown，和主线上 agent 的话一样。 |
| 后台任务那一行 | 任务图标（18px）和时间，放在这个回合开头。 |
| 系统行 | 现有的系统行。 |

读法只有一条：带头像字头的是槽位之间的话，不带的是写给你的话。主线上和展开后都一样。

### 正在跑

- 只在最下面那一行往来行上显示，而且只在槽位正在跑这个内部回合、你还没插话时。
- 时间的位置换成转圈，同一个位置、同样大。
- 预览换成它现在在做的事：正在跑的调用（“正在跑 Bash …”），没有就是它刚说的一句的第一行，带现有的流光。
- 不自己展开，行高不变，上面的东西不被顶走。你已经展开的，新内容在里面往下长。
- 回合结束，转圈换回时间，预览换成小结的第一行。
- 发给你的那条出现在这一行下面时，转圈还在上面这一行上，直到回合结束。

### 插话

- 和服务端的规矩一致（[产品说明](../product.md) §5.3）：你的消息并进内部回合以后，这个回合后面的话都交给你。
- 往来行在你的话之前结束。你的气泡照常出现在主线上，后面 agent 说的话整条显示，和你发起的回合一样。
- 输入框不变：内部回合在跑时照常能发，消息照现在的规矩排队、并进去。

### 发给你的

- 前面一个铃铛图标（灰色，和第一行对齐），后面一条竖线，再后面是正文。照原型 `SentMe` 的样子。
- 正文按 Markdown 显示，用和 agent 的话同一套样式（`MARKDOWN`）。
- 单个换行照原样换行，代码块里不动。agent 的话照旧按 Markdown 的规矩，单个换行不换行。
- 带的图和文件照现在的样子跟在正文后面。
- 铃铛的 `aria-label` 写“发给你的”。
- 位置：
  - 你的回合里：照旧在那次调用所在的折叠行下面。
  - 内部回合里：跟在这个回合所在的往来行后面。

### 折叠行

- 工具折叠行展开后，行上的摘要隐去但留着位置，换成“N 步”（N 是里面的行数，短话也算）；只有一步的，只写这一步的名字，不写参数。图标和箭头不动，行高不变。
- 里面每一步展开后，只留名字（工具名，或“思考”），参数和思考的开头隐去。
- 主线上的和往来行里的都这样。

### 宽度

- 在对话页顶栏“⋯”菜单的第一行：左边一个左右箭头图标和“宽度”，右边三个并排的选项“标准”“宽”“铺满”，当前的高亮。点了就换，菜单不关，好让你看着对话选。照原型 `WidthRow`，样子同终端的“字号”那一行。
- 三档：
  - 标准：对话栏最宽 48rem，就是现在的样子。
  - 宽：最宽 64rem。
  - 铺满：不限宽，两边留 1.5rem；对话栏是宽的时，右边多留出刻度条的地方。
- 跟着变宽的：消息、输入框、待发队列、提问卡片、信息卡，现在都是 48rem 的那些。终端那一面不变。
- 记在这台设备的 `localStorage` 里，键名 `chat-width`。标准是默认，不存。
- 对话区不比标准宽（48rem 加两边的空）时，三档看起来一样，菜单里没有这一行。按对话区的宽度算，不按设备：分栏、放大、侧栏收起都会变。
- 只在对话那一面有。槽位在终端里时菜单里没有这一行。

### 刻度条

- 一条短横对应一项：
  - 你的每句话（不带 `sender` 的你的话块），灰色；
  - 每行往来行，`--running` 的颜色。
- 当前那条：屏幕顶下 100px 那条线以上的最后一项；滚到底时是最后一项。点选一项后，目标进入视野就高亮这一项，直到你下次手动滚动再按位置判断。当前那条更长、颜色更深。
- 少于两项时不显示。只算已经取到的块：往上翻得越多，项越多。
- 宽、而且用鼠标时：
  - 一列短横贴着对话区右边，竖着居中，最高占对话区的 70%。
  - 短横之间 9px。放不下时间距缩小，最小 3px；还放不下，只画以当前那条为中心、放得下的那一段。
  - 指着一条，它变长，左边弹出预览：
    - 第一行是谁和时间：你的话写你的 Bot 头像和“你”；往来行写头像和名字，没有槽位的写任务图标和“后台任务”。
    - 下面是开头两行。你的话再加回复的开头两行，前面一条竖线。往来行写预览那句。
  - 点一条，平滑滚到那一项，顶上对齐。下方内容不足一屏时停在底部。
  - 预览用 Base UI 的 `Tooltip`。
- 窄、或者触屏时：
  - 贴着右边一条细线，短横更短更密，不能单独点。
  - 点细线弹出列表（Base UI 的 `Popover`）：每项一行字头（同上面预览的第一行）和一行开头，当前那项高亮并滚到中间。
  - 点一项，滚过去，列表关掉。
- 每条短横是一个按钮，`aria-label` 写“你：开头”或“<名字>：预览”。整条的 `aria-label` 写“刻度条”。
- 只在对话那一面有，终端那一面没有。

### `rh send` 从标准输入读

规则写在[产品说明](../product.md) §5.9，`rh` 怎么读写在[架构](../architecture.md) §9.1，页面怎么从命令里读正文写在[架构](../architecture.md) §7.7。这里只补：

- `-` 前后还有别的字时，`-` 当普通文字。
- 提示词只教 heredoc。别的给法（例如 `echo … | rh send me -`）照发，页面读不出正文，那一条只显示文件，没有文件就不显示。

### 提示词和回执

只改根槽位的两份系统提示（无头、TUI）、`rh send` 的帮助和一条回执。子槽位的不改：它的最终回复随汇报交给父槽位，本来就不用写成一句现状。

`src/prompt.ts` 无头那一份：

- 讲 `rh send me` 是什么的那条，最后一句“网页不算去处：你说的每一句话，网页上本来就看得到。”改成：
  > 网页不算去处。它发的话网页上整条显示，和你的回复一样排版。
- 讲推到哪的那条，“这一次发的内容网页上看得到，不用再写一遍；之后要说的话写在回复里就行。”改成：
  > 这时这条消息已在网页上整条显示，回复里不用再写一遍。
- 新加一条，紧跟在上一条后面：
  > - `rh send` 的正文用 Markdown 写，单个换行照原样换行。多行或带排版的，文字写成 `-`，从标准输入给正文，例如：
  >   ```
  >   rh send me - <<'EOF'
  >   正文
  >   EOF
  >   ```
- “别的消息开始的回合，最终回复不发回 IM。要让用户知道，用 `rh send me`。”改成：
  > - 别的消息开始的回合（内部回合），最终回复不发回 IM。要用户看的内容只走 `rh send me`。最终回复只写一句现状，例如在等什么，称用户为“你”：网页把这个回合折成一行，露出的就是这一句。发过 `rh send me` 的，最终回复不再说一遍它的内容。

TUI 那一份照旧从无头那一份里挑几条拼起来（`headless.slice(...)`）。新加的那条也要进 TUI 那份；“别的消息开始的回合”那条照旧不进。加了一条以后下标会变，实现时对一下拼出来的整份。

`src/commands.ts` 里 `rh send` 的帮助：

- 用法写成 `me|<平台>|<Bot 名> [--file <路径>]... [<文字>|-] | <工作区/槽位> <文字>|-`。子槽位那份写成 `me --file <路径>... | <工作区/槽位> <文字>|-`。
- “这一次发的内容网页上看得到，之后要说的话写在回复里就行。”改成“这时这条消息已在网页上整条显示，回复里不用再写一遍。”
- 加一句：“文字写成 - 时从标准输入读正文，例如 heredoc，多行和排版不受命令行引号限制。”两份帮助都加。

`src/router.ts` 没推送时的回执改成：

> 用户正在网页上看，没推送到 IM。这条消息已在网页上整条显示，回复里不用再写一遍。

## 你来验收

在开发环境上，手机和电脑宽屏都看，浅色和深色各一遍。找一个和别的槽位来回多的槽位（例如让两个槽位互相 `rh send` 几轮）：

- 你的回答后面只有一两行往来行，没有一串来信和最终回复。
- 往来行的头像、名字、预览、时间对得上；只发不收的是本槽位头像、箭头、对方头像。
- 点开看得到来信、发出的消息、过程和每个最终回复的全文；收起后行还在原处。
- 内部回合在跑时，只有最下面那行在转；跑完露出最终回复那一句。
- 内部回合在跑时你插一句，你的话后面的回复整条显示在主线上。
- agent 用 `rh send me - <<'EOF'` 发一条多行 Markdown：网页上带铃铛、排版和回复一样、单个换行是换行；IM 里也是多行。
- 网页开着时 agent 在内部回合里 `rh send me`：回执是新措辞，最终回复只有一句现状，没有把通知再讲一遍。
- 工具折叠行展开后写“N 步”。
- 宽度三档在宽屏上都试一遍，刷新后记得；手机上菜单里没有。
- 刻度条：电脑上指着出预览、点了跳；手机上点开列表、点了跳。

| IM 那边的任何变化 | 不变 |
| 发给你的那条下面的复制、引用键 | 按需 |
| 刻度条给还没取到的旧消息画短横 | 只画取到的，按需 |
| 页面从管道（`echo … \| rh send me -`）读出正文 | 提示词只教 heredoc，按需 |
